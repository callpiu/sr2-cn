# 成就进度显示 -1：v550 修复

## 原因与证据

SuperUI 的 `pause_menu_achievements_stats` 将有上限的统计值逐一与
`PAUSE_MENU_OF` 模板比较。简中资源中的该模板是 `{0}/{1}`，而原生统计
使用 `STATS_BLANK_OF_BLANK`，其中文格式为 `%d / %d`。
例如原生回调传入 `9 / 50`，脚本生成 `9/50`，比较失败后保留初始值 `-1`。

对当前进程只读检查确认统计分发器 `0x7779C0` 的 selector 1 指向
`0x77ECF0`；它从 `0x1452BE0` 统计描述表获取格式函数。
例如 CD（type 26）格式函数 `0x6B1E20` 调用 `0x7F4AD0` 查找
`0xE09824` 的 `STATS_BLANK_OF_BLANK`，而不是 `PAUSE_MENU_OF`。
两个模板也已按原生 CRC 在 `localization/text/static_CH.json` 中核实。

随后实机确认其余栏目恢复正常，但“快速暴怒”仍显示 `-1/28`。对新进程
12508 的只读核对表明：原生竞速统计 index 163/type 53 使用 `0x6B2010`，
在 `0x6B205C` 分支读取 `0x2527B2C` 的总数；当前值为 1，总数为 27，
所以回调传入 `1 / 27`。`common.vpp_pc` 中 `racing_sr2_city.xtbl` 也恰好
包含 27 条赛事定义，`Race_Number` 为 0–26。旧脚本写死的 28 是另一处独立错误。

## 修改范围

只在有上限统计的比较循环中额外生成 `{0} / {1}` 并比较，保留原模板匹配，
兼容原先紧凑格式。竞速成就的显示上限及完成判定由错误的 28 改为原生 PC
资源的 27，中文说明同步改为 27 场。不会把未知值强制归零，也不修改存档、
统计计数或 EXE。先前的菜单、清单、提示及描述汉化保留。

构建入口为 `tools/build_list_tips.py`。反向去除所有受管理修改后，Lua 必须
仍符合冻结的原始脚本哈希。CXT 只有竞速成就说明中的数字发生改变。

## 验证

`tools/verify_achievement_progress.py` 在 Lua 5.1 中运行真实回调与字符串比较
函数，使用资源中的实际中文模板。有上限的 27 个分支共 164 个案例，覆盖零、
中间值、满额、原菜单紧凑格式以及四类蓝领工作；另检查三个未改动的无上限/
现金路径，和未知输入不会被误判完成。竞速总数 27 来自独立的原生资源证据，
不再从待测脚本推导。另用真实菜单添加函数检查 0、1、26、27 四种进度的完成
标记与计数，确认 26/27 未完成、27/27 显示一颗完成星。

修复前重现 `-1`，修复后全部通过。完整脚本编译、原有显示回归和项目校验通过。
引擎文本转换在离线测试中为模拟。2026-10-26 用户重启并读取同一存档后明确
确认“进度和说明都正常”，完成竞速进度 `/27` 与中文说明的实机验证。
真实存档达到 27/27 时的完成标记尚未实测，其边界由上述 Lua 回归覆盖。
