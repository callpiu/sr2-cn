## 0. 一句话结论

> **引擎加载的中文字形表 `common.vpp_pc/fnt_chinese.vf3_pc`（2838 项）是一张"错的表"——

## 2. 根因链条（每一环都有实证）

### 2.1 引擎选字体的语言分支（SR2_pc.exe 反汇编）
```
0xE8C470 = 语言索引；中文 = 13 (0xD)
0x51D408: cmp eax, 0xD
0x51D40D: mov ecx, 0xDE0FD0   ; "fnt_chinese"
```
⇒ 中文时引擎加载字体名 `fnt_chinese`。

### 2.2 两张同名 vf3 的真实差异（本轮核心）

用 **u32** 正确读取后：

| | `common.vpp_pc/fnt_chinese.vf3_pc` | `patch.vpp_pc/fnt_chinese.vf3_pc` |
|---|---|---|
| 项数 N | **2838** | **2795** |
| 字节 | 68300 | 67268 |
| U 唯一值个数 | **307**（最小间隔 1px，1..2023 杂乱） | **65**（间隔恒为 **31**，1..1985） |
| V 唯一值个数 | 41（间隔 31，1..1241） | 43（间隔 31，1..1303） |
| U 语义 | **字距 / kerning**（非坐标） | **图集列坐标**（31px 网格） |
| 与 31px 图集格 | ❌ 不匹配 | ✅ 完全对齐 |

**两张图集（patch 的 `g_peg_pc` 与 textures 的 `fnt_chinese`）实测网格都是 31px**
（列块起点间隔 31/32/30 交替 = 抗锯齿导致的 ±1px，本质 31）。
⇒ 图集没问题，**问题在 common 的那张 vf3**。

### 2.3 渲染实证（`_E26_engine_compare.png`，索引 = idx = slot − 0x20）

用同一个正确索引，换不同 (vf3, 图集) 组合：

| 组合 | 结果 |
|---|---|
| **patch.vf3 + patch 图集** | `你的弟兄们需要你的保护` ✅ |
| **patch.vf3 + textures 图集** | `你的弟兄们需要你的保护` ✅ |
| common.vf3 + textures 图集 | `交 烬层 伟 为迫 腊 交 烬仑 E 恕` ❌ ← **真机乱码来源** |
| common.vf3 + patch 图集 | 同上 ❌ |

⇒ **唯一变量是 vf3**。图集用哪张都行。

### 2.4 为什么是"乱序"而不是"平移"
common 的 U 是字距值（0..2023 连续分布、间隔 1），被当作 31px 网格的列坐标去索引，
每个字落到的格子与正确格子毫无算术关系 ⇒ 表现为**置换**。

## 5. 关键技术事实（供后续参考）

```
■ vf3 结构（真实）
   文件 = 0xBC 头 + N*16 记录 + N*4 U(u32) + N*4 V(u32)
   patch  N=2795: 0xBC + 44720 + 11180 + 11180 = 67268 ✓
   common N=2838: 0xBC + 45408 + 11352 + 11352 = 68300 ✓
   记录 = (u16 字宽, u16 ?, u16 字宽, u16 ?)   ← 无码点字段

■ le_strings 结构
   头: magic u32 = 0xA84C7F73, ver u16, buckets u16(=1024), count u32
   桶表 @12 (buckets*8)，指针数组 @12+buckets*8 (count*4)
   记录 @off: u16 id1, u16 id2, 然后 slot 序列 —— ★ 大端 u16，遇 0x0000 结束
   hash = (id1<<16)|id2

■ slot ↔ 索引
   charlist_CH 有 2795 项（第 i 项的 slot = i + 0x20）
   引擎查 vf3 用 idx = slot − 0x20
   ASCII 段（slot < 0x20+224）与 CJK 段统一

■ 引擎地址（SR2_pc.exe，ImageBase 0x400000，无 ASLR）
   0x7F4430 loadcharlist       0x7F4CF0 get_language_code
   0x7F4D60 get_localization_from_hash（被 DFEngine 挂钩）
   0x7F4E30 校验  0x7F4EE0 slot→codepoint  0x7F4F20 codepoint→slot
   CHARLIST_PTR 0x02528B2C   NUM_CCHARS 0x02528B30   LANG 0xE8C470
   字体名表 0xDE0FCC..0xDE1040（0xDE0FD0 = "fnt_chinese"）

■ DFEngine.dll（MStrings 本地化模块，PDB 已解析）
   MStrings::loadcharlist 0xACCC0     get_localization_from_hash 0xAB370
   钩子目标 0x100AB370 → SR2_pc.exe!0x7F4D60
```

## 7. 防坑记录（新）

1. **vf3 的 U/V 是 u32**。用 u16 读只会看到 `2,0,20,0,38,0…` 这种假象（偶数项为 0 其实是高 16 位）。
2. **le_strings 的 slot 是大端**。用小端解出来是一串无意义的乱槽。
3. **两张 fnt_chinese 图集内容不同，但网格尺寸相同（31px）**。不要以为换图集能解决问题。
4. **看图认字要放到足够大**。`值督忍写住颏证值督充拯` 曾被误读成 `你的弟兄们需要你的保护`（都是常见字、笔画相近）。
5. **VPP entry 结构**：`(u32 name_off, u32 ext_off, u32 ?, u32 body, u32 size, u32 0xFFFFFFFF, u32 0)`，
   `body`/`size` 是相对 `data_start` 的偏移与长度。
6. 改 size 字段用 `struct.pack_into('<I', data, entry_off + 16, newsize)`。
