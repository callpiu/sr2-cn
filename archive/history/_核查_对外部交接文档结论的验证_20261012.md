## 三 · 最关键的证据：字形映射在两条串里【高度一致】

把中文与用户转写的乱码逐位对齐：

```
REC1 中文: 你 的 弟 兄 们 需 要 你 的 保 护
REC1 乱码: 任 璨 偶 巧 位 雄 衡 任 璨 伪 该

REC2 中文: 你 的 弟 兄 们 要 出 去 谈 几 笔 生 意 ， 保 护 他 们 免 遭 袭 击
REC2 乱码: 任 璨 偶 巧 位 校 衡 勾 远 藐 乱 携 ？ 空 伪 该 亡 位 通 像 匪 冰 挺 拮
```

两条串里**完全一致**的映射：

```
你 → 任     的 → 璨     弟 → 偶     兄 → 巧     们 → 位
保 → 伪     护 → 该
```

**7 个字在两条独立记录里映射到同一个字**——随机文本不可能做到。
这证明屏幕上那串乱码的字，**就是这两条记录里的字经过一套固定的字形重排**（你→任、的→璨…）。
（"你"在 REC1 里出现 2 次，两次都渲染成"任"，同样自洽。）

## 四 · 那"改了没变化"怎么解释？——该轮实验的方法缺陷

**这是重点**：之前所有探针实验（ASCII、25 条打标、车耐久、空格填充）**全部是等长替换**，
即用空格把长度补回 11/22 字。

后果：**屏幕上的字数永远是 11/22**，所以"字幕看起来没变化"这个观察**根本没有判别力**——
它既不能证明"是这条"，也不能证明"不是这条"。

而且用户反馈过"你给我把别的文字全弄不见了"——说明那批改动**确实生效并被游戏读取了**。
两条事实放在一起，指向的不是"数据来自别处"，而是**上一轮实验设计有缺陷**。

## 五 · 建议的下一步：变长探针（5 分钟，不需要 Cheat Engine）

脚本已就绪：`F:/sr2-cn/probe_vary.py`

```bash
python probe_vary.py apply     # 把 REC1 改成 3 个字「壹贰叁」（自动备份）
#   → 进游戏，进入直升机突击活动，看字幕变成几个字
python probe_vary.py restore   # 看完还原
```

判定标准非常干脆：

| 屏幕显示 | 结论 | 后续 |
|---|---|---|
| **3 个字** | 字幕就是 REC1，之前"没变化"是观察/加载问题 | 字形重排可解：用连续索引探针读出真实字形表，再反查修正 |
| 仍是 **11 个乱码** | 字幕确实来自别处 | 此时才值得上 Cheat Engine |

**注意**：如果要上 Cheat Engine，搜索目标也该改——
不要搜乱码字（渲染产物，未必以字符串形式存在于内存），
应搜**探针文本本身**（如把 REC1 改成 `SR2PROBEAA` 后搜这个 ASCII 串）。
搜到 = 记录被读取（问题在渲染层）；搜不到 = 记录没被读（问题在加载层）。
