## 3. PEG / 图集格式要点（已逆向）
- `.peg_pc` = 72 字节 GEKV 头 + 以 `\0` 结尾的 `"name.tga"` 文件名。
- `.g_peg_pc` = **无头**，纯 DXT3 mip 链。引擎要求**完整 mip 链**，否则扫描阶段崩溃（此前 top-level-only 导致全字幕消失，已解决）。
- mip 约定：每维 `max(1, x//2)` 递减，block 维 `ceil(dim/4)`，约 10 级。
- 单条目 `.xtbl`（BitmapSheets）即可注册图像名；无需自有 `.xtbl` 也能被 `juiced-ui.xtbl` 引用。

---

## 4. 图集字形定位（关键逆向结果）
- 图集 2048×2048 DXT3，每格 31×31，字形居中。
- v10 汉化 vf3（N=2795）的 U/V 数组布局（已验证与 `f.uv` 完全一致，0 处不一致）：
  ```
  b = k // 65;  p = k % 65
  if p < 60:  x = 156 + 31*p;      y = 1 + 31*b
  else:       x = 1 + 31*(p-60);   y = 1 + 31*(b+1)
  ```
- 注意 vf3 的 V 数组在末尾**缺 5 项**（k≥2790 读越界）。k≥2790 直接用上面公式（逗号 `，` 在 idx=2790，正好在断点）。

## 5. ★ 本回合最重要发现
- 用 **v10 汉化 patch 自带的图集（md5 340340761dda）** 按上面坐标取字，得到的是**乱码字形**（使 盈 弱 克 份 霸 视…），不是「你的弟兄们…」。
  ⇒ v10 汉化 patch 自带图集的**字形顺序与它的 charlist 不一致**（这本身就是原 bug 的一部分）。
- 三个候选图集（均 4MB / 2048×2048 DXT3）：
  | 来源 | md5 | 结论 |
  |---|---|---|
  | 官方原版 patch 图集 `backup_original/patch.vpp_pc` | `a8c33f126943` | **可用**（见下） |
  | v10 汉化 patch 图集 | `340340761dda` | **已证伪**（取字乱码，禁用） |
  | 游戏 `textures.vpp_pc` 图集 | `62a57046a590` | 备选，未验证 |
- 之前 `_HO_cells.png` 实证：官方图集 `idx336=任、idx371=你、idx1784=璨、idx1836=的、idx2342=该、idx2656=雄`
  ⇒ **官方图集顺序 = charlist**（idx(k) 位置即 charlist[k] 的字形）。
- 结论：**正确字形必须来自官方图集 `a8c33f126943`**，坐标仍用上面 grid_xy（基于 v10 汉化 vf3 的 U/V）。
