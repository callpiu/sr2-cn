## 一 · 我承认的两个错误（核查说得对）

### 错误 1：我实验设计的判别力问题（部分成立）

核查指出：
> 之前所有探针实验全部是等长替换 + 空格补齐，
> 屏幕上的字数永远是 11/22，所以「字幕没变化」这个观察**没有判别力**。

**部分成立**：
- 「变长探针」（REC1 → 3 个字）**确实**有这个问题 ——
  probe_vary 把 REC1 改成了 **3 个槽位**，屏幕上只剩 3 个字形位置，
  但如果字幕不来自 REC1，屏幕仍是 11 个乱码，看起来"没变"。
  → **这一轮的判别力确实弱。**

- 但 **ASCII 探针没有**这个问题：
  `PROBE-A HOMIES PROTECTION` 是拉丁字母，若渲染出来必然与汉字完全不同。
  屏幕仍是汉字 → 有判别力。

## 二 · 核查文档的核心论证被实测证伪

### 它的论证

> 两条串里完全一致的映射：你→任 的→璨 弟→偶 兄→巧 们→位 保→伪 护→该
> **7 个字在两条独立记录里映射到同一个字** —— 随机文本不可能做到。

### 实测结果（`verify_mapping_claim.py`）

```
REC1 逐位映射（11 字）:
   你→任  的→璨  弟→偶  兄→巧  们→位  需→雄  要→衡  你→任  的→璨  保→伪  护→该

REC2 逐位映射（22 字）:
   你→任    的→璨    弟→偶    兄→巧    们→位      ← 与 REC1 一致 ✓
   要→校 ★  出→衡    去→勾    谈→远    几→藐
   笔→乱    生→携    意→伪    ，→该    保→亡 ★
   护→位 ★  他→通    们→像 ★  免→匪    遭→冰
   袭→挺    击→拮

★ 冲突 4 处:
   要: REC1→衡  vs  REC2→校
   保: REC1→伪  vs  REC2→亡
   护: REC1→该  vs  REC2→位
   们: REC1→位  vs  REC2→位/像
```

**结论：「映射一致」不成立。** 有 4 个字（含「们」在 REC2 内部就冲突：位 vs 像）
映射到不同结果。

所以：
- 前 5 个字（你/的/弟/兄/们）一致 —— 因为它们**恰好占据相同位置**（0..4）
- 第 6 个字起就分叉 —— 因为 REC1 的「要」在第 6 位、REC2 的「要」在第 5 位

**这正是「位置相关映射」的特征，不是「固定字形重排」。**
核查的论证只看了前 5 位就下了结论。

## 三 · 新增的决定性实验（ASCII 原地探针）

### 设计（修正了判别力问题）

```
把 REC1 的前 11 个槽位【原地】改成 ASCII 字母 A..K
  → REC1 新文本 = "ABCDEFGHIJK"（11 个拉丁字母）
  → 条目大小/偏移完全不变（只改 22 字节），VPP 结构零改动
```

### 结果（用户 15:51 实测）

```
屏幕字幕：仍是 11 个【汉字】乱码（任璨偶巧位校衡…）
```

**拉丁字母不可能渲染成汉字。** 所以：
```
★ 字幕不来自 REC1 —— 这是硬结论
```

### 附带结论

REC2 在更早的探针里也被换成过 `PROBE-B HOMIES DEALS PROTECT THEM`（纯 ASCII），
屏幕同样是 11/22 个汉字乱码 → 同样不来自 REC2。

## 四 · 目前的确切结论

```
✓ 字幕不来自 REC1（ASCII 原地探针，硬结论）
✓ 字幕不来自 REC2（ASCII 探针 + 等长探针）
✓ 25 条候选记录全部打标记后无反应
✓ 乱码字不存在于任何磁盘文件（6 种编码 × 3433 文件）
✓ 「字形映射一致」论证不成立（4 处冲突）

? 那 22 个字与 REC2 的中文字符数吻合、前 5 位映射吻合 —— 仍是未解之谜
```

**一个仍未排除的重要可能**：
字幕可能是**在游戏启动时从 REC2 读取并缓存在内存里**的。
探针改的是启动后的文件，若游戏在更早的时刻（或另一个进程/模块）读过一次，
内存里的旧串就会持续显示。

→ 这也是**为什么建议用 Cheat Engine 搜内存**的原因：
搜索目标应该是**探针文本本身**（如 `ABCDEFGHIJK` 的 UTF-16 表示），
而不是乱码字（乱码是渲染产物，未必以字符串形式存在于内存）。

## 五 · 建议的下一步（修正版）

### 步骤 1：确认 REC2 是否参与（5 分钟）

我用同样的原地探针做了 `probe_rec2abc.py`（把 REC2 前 11 槽位改成 ASCII）。
用法：
```bash
python probe_rec2abc.py apply     # 应用
python probe_rec2abc.py restore   # 还原
```
若屏幕出现拉丁字母 → REC2 参与；若仍是汉字 → REC2 也不参与。

### 步骤 2：若仍无反应 → 内存搜索（唯一出路）

```
Cheat Engine 附加 SR2_pc.exe
1) 应用 probe_abc.py（REC1 = ABCDEFGHIJK）
2) 搜 "ABCDEFGHIJK" 的 UTF-16LE：41 00 42 00 ... 4B 00
   - 搜到 -> 记录被读取，问题在渲染层（字形映射）
   - 搜不到 -> 记录根本没被读，问题在加载层
3) 再搜乱码字「任璨」的 UTF-16LE：FB 4E A8 74
   - 找到后 "Find out what accesses this address" -> 定位读取者
```
