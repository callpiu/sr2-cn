## 0. 本轮一句话

**已把引擎内字表子系统完整反汇编定案**（加载器/校验/双向转换/第二表），并**发现当前补丁字表与官方原版字表在索引 224 起就整体错位**（官方 2838 项含日文假名；当前补丁 2795 项已删假名）。乱码极可能是**「用 A 表算出的索引 / 用 B 表查字」**导致，但**静态穷举尚未 100% 复现**，仍需一次**运行时字表转储**定案。

## 1. 本轮新增的硬结论（可直接复用）

### 1.1 ★ 引擎字表子系统全部函数（静态 VA = 绝对地址，无 ASLR）

| 函数 | 作用 | 记录/语义 |
|---|---|---|
| `0x7F4430` | **charlist 加载器**（由 `0x7F46A0` 统一初始化函数调用） | 见下 |
| `0x7F46A0` | 字体总初始化：清 8 个字体槽(`0x1FD5338`,每 0x54)→加载2个字体(`0x7F4780`)→加载 CONTROL_OKAY/YES/NO→**调 `0x7F4430` 加载 charlist**→置 `[0x2528B0F]=1` | |
| `0x7F4E30` | **校验器**：对每个 UTF-16 字符线性扫表，比 `charlist[i]&0xFFFF`，命中通过；表值 > 目标即判失败→替换为 `_`(0x5F)，并置 `[0x2528B28]=1` | 假定表**按码点升序** |
| `0x7F4EE0` | 字形索引 → 码点：比 `+2`(高16)，返回 `+0`(低16) | 线性 |
| `0x7F4F20` | 码点 → 字形索引：比 `+0`，返回 `+2` | 线性（**0 个调用者**） |
| `0x7F4F60` | **compress_char**：比 `+0`(码点)，命中返回 `+2`(字形)，`edi` 出 flag；输入 <0x100 直接返回 | 线性 |
| `0x7F4FA0` | 字形索引串 → 码点串（**反查**），逐个调 `0x7F4EE0` | 0 个调用者 |
| `0x7F5030` | **码点串 → 字形索引串**（渲染主入口），逐个调 `0x7F4F60` | **11 个调用者** |

**`0x7F5030` 的 11 个调用者**（渲染路径）：
`0x75D5A0, 0x80DB76, 0x81590C, 0x8160AC, 0x816EFC, 0x819B5A, 0x819E6C, 0x819F25, 0x839C05, 0x863255, 0x9D42E5`

**校验器 `0x7F4E30` 的 4 个调用者**：
`0x80DB5B, 0x839BF3, 0x863243, 0x9D42D6`

其中 `0x80DB5B`+`0x80DB76` 同一函数（标准管线），`0x9D42D6`+`0x9D42E5` 同一函数（**独立管线，疑似 HUD/活动字幕**）。

### 1.2 字表全局变量全清单

```
0x2528B2C  charlist 指针      0x2528B30  num_cchars
0x2528B28  "出现外来字符"标志  0x2528B29  flag
0x2528B2A  flag              0x2528B34  第二表指针(待渲染列表)
0x2528B38  第二表计数          0x2528B48  高频全局(896处引用,非字表)
0x2528E58 ... (0x7F4xxx 簇里密集使用的其它全局)
```

引用 `0x2528B2C` 的**写操作只有 2 处**：`0x7F4461`(清零)、`0x7F466A`(写入 alloc 结果)。**唯一写入者就是 `0x7F4430` 加载器。**

### 1.3 ★★ 官方原版字表 vs 当前补丁字表：**索引 224 起整体错位**

| | 官方原版(pristine) | 当前补丁 |
|---|---|---|
| 项数 | **2838** | **2795** |
| 格式 | 带 `//注释头` + `count=2838` 头 + `\r\n` | 纯数字 + `\n`，无头 |
| 索引 0..223 | ASCII 32..255 | ASCII 32..255（**相同**） |
| 索引 224.. | 8217,8230,8231,8592(←),8593(↑),9472(─),12288,0x304A(ぉ)... | 0x2014(—),0x201C,0x2026,0x3001,0x4E00... |
| 特点 | **含日文假名**(0x304x-0x309x) | **已删假名**，直接进汉字 |

**⇒ 官方表 2838 项 = common 字体 2838 字形数（完全吻合！）**
**⇒ 当前补丁表 2795 项 ≠ common 字体 2838（少 43 项）**

**这是本轮最重要的发现：补丁把官方字表「删字缩编」了，导致索引整体前移。**

## 3. 下一步（唯一能定案的路径）

**必须拿到「运行时字表」**。当前游戏进程(PID 4868)处于 `num_cchars=0`（未加载 CJK）。

做法二选一：
- **A(推荐)**：用户在游戏里进入能显示中文的界面（主菜单/游戏中），使 `[0x2528B30] != 0`，然后运行 `live_state.py` dump 完整运行时字表 → 与磁盘表逐项比对，看**运行时表究竟是 2795 还是 2838 项**。
  - 若是 2838 ⇒ **HUD 用了另一张表**，根因锁定
  - 若是 2795 ⇒ 表一致，问题在"码点→字形"的查询用了**另一套索引**
- **B(需用户同意)**：远程调用 `0x7F4430` 强制加载，再调 `0x7F4F60` 实测 9 字映射（有崩溃风险）
