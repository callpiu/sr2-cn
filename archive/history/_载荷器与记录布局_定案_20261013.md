# 字表加载器 0x7F444A 与记录布局 —— 反汇编定案

---

## 一、加载器 `0x7F444A`：记录布局是「低16=**字形索引**，高16=**码点**」

关键指令段（`0x7F45E7`–`0x7F462E`）：

```asm
0x7F45E7  mov  dword ptr [esp+0x20], 0x100        ; cx 初值 = 256
0x7F45F1  cmp  ebx, [esp+0x10]                    ; i >= count ?
0x7F45F5  jae  0x7F465E
0x7F45F7  lea  ecx, [esp+0x14]
0x7F45FB  push ecx
0x7F45FC  push 0xE2608C                           ; 格式串
0x7F4601  push esi                                ; 行指针
0x7F4602  call 0xC97089                           ; sscanf(line, fmt, &w)
0x7F4607  mov  ax, word ptr [esp+0x20]            ; ax = 0x100 (码点!), 每次 +1
0x7F460F  add  ebx, 1                             ; i++
0x7F4612  cmp  ax, 0x100
0x7F4616  jae  0x7F461D                           ; 码点 >= 0x100 分支
0x7F4618  movzx ecx, ax                           ; ASCII: ecx = 码点本身(=字形索引)
0x7F461B  jmp  0x7F462B
0x7F461D  mov  edx, [esp+0x20]
0x7F4621  movzx ecx, dx                           ; ecx = 当前码点 (old)
0x7F4624  add  edx, 1
0x7F4627  mov  [esp+0x20], edx                    ; 码点自增 (new)
0x7F462B  mov  word ptr [edi], ax                 ; ★ 记录 +0 = ax = 码点
0x7F462E  mov  word ptr [edi+2], cx               ; ★ 记录 +2 = cx = 字形索引
0x7F4634  add  edi, 4                             ; 记录步长 4 字节
```

**⇒ 记录 = `<u16 码点> <u16 字形索引>`**

- `+0`(低16) = **码点**（就是文件里的值）
- `+2`(高16) = **字形索引**，ASCII（<0x100）时 == 码点本身；非 ASCII 时从 **256** 起**按行序自增**

**⚠️ 这与 `_交接_20261013.md` 第 81 行「低16=码点，高16=kerning/宽度索引」一致，但更精确：高16 = 字形索引（glyph index），由加载器从 256 起顺序分配。**
**⚠️ 也与 07 年 A5 文档「高16 = 0x0020..0x0B35」观测吻合：那是 ASCII 区（32..255 → 0x20..0xFF）之后进入 0x100 起的非 ASCII 索引。**

## 二、`0x7F4E30` 校验器：线性升序早退，未命中替换为 `_`

```asm
0x7F4E5B  xor  eax, eax                    ; eax = 0
0x7F4E61  movzx edx, word ptr [edi]        ; edx = 输入字符 (UTF-16)
0x7F4E64  movzx ecx, word ptr [ebp+eax*4]  ; ecx = charlist[eax] 低16 = 码点
0x7F4E69  cmp  cx, dx
0x7F4E6C  je   0x7F4E81                    ; 命中 -> 下一个字符
0x7F4E6E  ja   0x7F4E76                    ; 表值 > 目标 -> 判失败
0x7F4E70  add  eax, ebx (ebx=1)
0x7F4E72  cmp  eax, esi
0x7F4E74  jb   0x7F4E64
0x7F4E76  mov  word ptr [edi], 0x5F         ; '_' 替换
0x7F4E7B  mov  byte ptr [0x2528B28], 1      ; 置「出现外来字符」标志
```

**⇒ 校验器比较的是记录 `+0`（码点），并要求表按码点升序。命中即通过；表项码点 > 目标码点即判「不存在」。**

## 三、四个半字函数确认

| 函数 | 比较半字 | 返回半字 | 语义 |
|---|---|---|---|
| `0x7F4EE0` | `+2`(字形索引) | `+0`(码点) | 字形索引 → 码点 |
| `0x7F4F20` | `+0`(码点) | `+2`(字形索引) | 码点 → 字形索引 |
| `0x7F4F60` | `+0`(码点) | `+2`(字形索引) | 码点 → 字形索引（带 flag 出参） |
| `0x7F4FA0` | 逐个调 `0x7F4EE0` | 拷到目标缓冲 | 字形索引串 → 码点串（**反查**） |
| `0x7F5030` | 逐个调 `0x7F4F60` | 拷到目标缓冲 | 码点串 → 字形索引串 |

四者均为**线性搜索**，无排序假定（`0x7F4F60/0x7F4F20/0x7F4EE0` 都是 `cmp` 相等即返回，不做大小早退）。

## 四、对乱码的直接意义

乱码串是**显示出来的字**（位/任/伪/巧/偶/该/璨/衡/雄），即「字形索引 → 码点反查」(`0x7F4FA0`) 的产物。

设磁盘 REC 的 slot 序列其中一项字符码点为 X（如「你」=0x4F60）：
1. 引擎先 `0x7F4E30` 校验 X，命中（REC 数据正确）✓
2. `0x7F5030` 把 X 转成**字形索引 g**（`0x7F4F60`，匹配码点返回 `+2`）
3. 渲染时（或日志/回读时）若走了 `0x7F4FA0` 把 g 反查成码点，得到的就是**另一个字的码点**

⇒ **若第 3 步用「同一张表」反查，必然回到 X 本身，不可能错位。**
⇒ **错位只能来自：`g` 是在「表 A」里算出的，而被拿到「表 B」里反查。**

**这正好对应 `_交接_20261013.md` 的推论 (c)：slot→码点转换正确，错误发生在「码点→字形」这一步用了不同的表。**
