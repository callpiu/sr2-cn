## 2. ★ le_strings 格式（本轮彻底破解，取代此前所有版本）

```
magic(4) = 0xA84C7F73
ver(2) + buckets(2)
count(4)              # 记录数
[count * u32]         # 偏移表，位于 16 + buckets*8，每项=记录体的绝对偏移
-------- 记录体（在偏移处）--------
u16 hash
u16 pad
UTF-16BE 文本        # ★ 注意是 BE！不是 LE！
u16 0x0000           # 终止
```

**unit 编码**：
- `unit < 0x100` → ASCII，直接是字符
- `unit >= 0x100` → **压缩槽位 slot**

---

## 3. ★ 引擎建表算法（`SR2_pc.exe!0x7F4430 loadcharlist`）

`0x7F45E7` 处：`C7 44 24 20 00 01 00 00` = `mov dword ptr [esp+0x20], 0x100`
（全 exe **唯一**出现；**SR2_pc.exe 未被 patch**，逻辑为原版）

```asm
7F4607: mov  ax, [esp+0x20]      ; ax = 当前 codepoint
7F4612: cmp  ax, 0x100
7F4616: jae  7F461D
7F4618: movzx ecx, ax            ; <0x100 → slot = codepoint
7F461B: jmp  7F462B
7F461D: mov  edx, [esp+0x20]
7F4621: movzx ecx, dx            ; >=0x100 → slot = 计数器
7F4624: add  edx, 1
7F4627: mov  [esp+0x20], edx     ; 计数器++
7F462B: mov  [edi], ax           ; 表项[0] = codepoint
7F462E: mov  [edi+2], cx         ; 表项[1] = slot
```

**即**：为 charlist 每个字符建立 `<codepoint, slot>` 对。
- ASCII（<0x100）→ `slot = codepoint`
- 非 ASCII → `slot = 256 + (该字符在本表中的非ASCII序号)`

**推导**：
| 表 | ASCII 前缀 | slot 公式 |
|---|---|---|
| `charlist_CH`（2795 项） | **224 项**（idx0..223 = 0x20..0xFF） | **slot = idx + 32** |
| `charlist_CZ/JP/PL/RU/SK/JPCharList` | **0 项** | slot = idx + 256 |

## 5. 矛盾：磁盘全对，实机仍乱

**⇒ 唯一可能：引擎运行时加载的 charlist ≠ `patch.vpp_pc/charlist_CH.txt`。**

候选原因（待验证，按嫌疑排序）：
1. **`juiced.ini` 的 `ForceLanguage=NA`**（NA 是非法值；注释列 EN,DE,FR,ES,IT,NL,SE,DK,PL,CZ,RU,CH,JP）
   → JUICED 可能据此选了非 CH 语言 → 加载了别的 charlist（ASCII 前缀不同 → 全部中文字位移）
2. JUICED/DFEngine 的 loose 加载路径优先拿到了别的 charlist
3. 语言码判定（`get_language_code @0x7F4CF0` / `[0xE8C470]`）与 charlist 名不匹配
